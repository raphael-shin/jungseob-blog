## TL;DR

- Prospero는 명령의 대기 시간 초과를 백그라운드 전환으로 처리하고, 중단할 때는 프로세스 트리를 함께 정리한다.
- 응답 없는 권한 요청은 거부로 끝내지만, Plan 모드는 사용자를 계속 기다리는 예외다.
- 원격 엔진과 GUI를 분리하며, 권한 확인을 보안 격리와 구분한다.

Chris Wellons는 밤새 코딩 에이전트를 돌려 놓고도 사소한 문제에서 멈춘 채 아침을 맞는 경험을 반복했다. 오래 걸린 빌드를 중단했는데 자식 프로세스가 살아남아 다음 빌드와 충돌하는 문제도 겪었다. 그가 만든 Prospero는 이런 실패를 하네스의 실행 규칙으로 다룬다. 기다리는 시간에 한도를 두고, 명령을 멈출 때는 프로세스 트리 전체를 함께 정리하는 설계다.

## 시간 초과 뒤에도 작업 상태를 잃지 않는다

Prospero에서 셸 명령의 시간 초과는 곧바로 작업 종료를 뜻하지 않는다. 명령을 비동기 백그라운드 작업으로 전환한다. 에이전트는 다시 제한 시간을 정해 기다릴 수 있고, 주기적으로 깨어나 계속 기다릴지 판단한다. 반대로 사용자가 명령을 중단하면 하위 프로세스까지 함께 멈추는 것이 설계 원칙이다. 기다림과 중단을 다르게 처리해 이미 실행 중인 빌드를 무심코 다시 시작하는 문제를 줄이려 한다.

권한 요청도 응답 없이 무한히 대기하지 않는다. 제한 시간이 지나면 거부로 처리하고 에이전트는 그 권한 없이 진행해야 한다. 네트워크 요청에는 시간 제한을 두고 에이전트 간 메시지함에도 용량 한도를 둔다. 다만 Plan 모드는 예외다. 사용자가 곁에서 계획을 검토한다는 전제여서 계획 제시나 확인 질문 뒤에는 계속 기다린다.

## 창과 실행 엔진의 수명을 분리한다

Prospero는 C++과 Dear ImGui로 만든 네이티브 프로그램이다. 일반적인 실행에서는 창과 엔진이 같은 프로세스에 있지만, 같은 실행 파일을 화면 없이 구동할 수도 있다. 엔진을 원격 호스트에 두고 개인 컴퓨터에서 화면만 연결하는 구성이 가능하다. GUI를 닫아도 계속 실행하도록 설정한 뒤 나중에 다시 연결할 수 있다.

화면 자체도 매 프레임 계속 다시 그리지 않는다. 애니메이션을 마무리한 뒤 변화가 없으면 렌더링을 쉬게 한다. 빌드가 끝나기를 기다리는 동안 화면 갱신에 GPU 자원을 쓰지 않으려는 선택이다. Wellons는 다른 하네스보다 자원 사용량이 크게 적다고 주장하지만, 소개 글에는 비교 대상과 측정 조건을 갖춘 벤치마크가 없다. 이 노트에서도 직접 실행해 성능을 측정하지 않았다.

## 권한 창은 격리 경계가 아니다

모델 서비스는 기본으로 설정돼 있지 않아 사용자가 로컬 모델 서버나 호환 API를 연결해야 한다. 원격 배포용 엔진을 내장한 Professional 배포판과 그렇지 않은 Community 배포판도 구분된다. 공식 원격 문서는 별도로 준비한 엔진을 찾는 경로를 설명한다. 따라서 Community에서 원격 실행 자체가 불가능하다기보다 필요한 엔진을 사용자가 준비해야 하는 차이에 가깝다.

설정을 URL로 공유할 수 있어도 그 주소를 신뢰할 필요는 남는다. 원격 설정이 셸 명령에 영향을 주는 항목은 제한하지만, 환경 변수 값을 API 키로 읽어 설정 제공자가 통제하는 엔드포인트로 보내는 위험까지 없애지는 못한다. 권한 확인 역시 악의적인 에이전트를 막는 격리 장치로 설명하지 않는다. 접근을 강하게 제한하려면 하네스 자체가 접근할 수 있는 자원을 컨테이너나 별도 장비로 제한해야 한다는 것이 Wellons의 경계 설정이다.
